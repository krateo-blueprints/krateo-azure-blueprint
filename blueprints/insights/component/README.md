# Krateo Blueprint — Azure Insights Component

> Generated by `tools/asogen` from the Azure Service Operator `Component` CRD (`insights.azure.com`).

Provisions an Azure Insights **Component** through
[Azure Service Operator](https://azure.github.io/azure-service-operator/). The chart renders a
native `insights.azure.com/v1api20200202` `Component` resource; ASO reconciles it into the real
Azure resource and reports status back.

Once the `CompositionDefinition` is applied, every `AzureInsightsComponent` Composition you create
becomes an Azure Component.

This CRD serves **2** versions upstream; this blueprint targets
`v1api20200202`, the newest GA non-storage version.

## Prerequisites

- **Azure Service Operator installed** in the cluster — see
  [`../../../docs/installing-controllers.md`](../../../docs/installing-controllers.md).
- **Azure credentials configured** — Workload Identity (recommended) or a service-principal
  Secret. See [`../../../docs/authentication.md`](../../../docs/authentication.md).
- Krateo `core-provider` installed.

## Configuration

Composition `spec` fields **mirror the ASO Component spec**, including the required `owner`
reference and `location`. Full schema in [`chart/values.schema.json`](chart/values.schema.json).
The extra `credentialFrom` field sets the `serviceoperator.azure.com/credential-from` annotation;
leave it empty to inherit the credential from the namespace.

## How to install

Register it with the CompositionDefinition attached to a release of this repository, stamped
with that release's chart version. The `compositiondefinition.yaml` beside this README carries
the `CHART_VERSION` placeholder, which only the release replaces, so it is not meant to be applied.

```sh
VERSION=X.Y.Z   # a release of this repository: https://github.com/krateo-blueprints/krateo-azure-blueprint/releases
kubectl create namespace azure-insights-system
kubectl apply -f "https://github.com/krateo-blueprints/krateo-azure-blueprint/releases/download/${VERSION}/compositiondefinition-azure-insights-component.yaml"   # publishes the AzureInsightsComponent type
kubectl apply -f customform.yaml              # optional: portal card + form
```

This publishes a `AzureInsightsComponent` Composition type (`composition.krateo.io/vX-Y-Z`, the release
version with dashes, e.g. `0.1.6` → `v0-1-6`; plural `azureinsightscomponents`), pulling the chart from
`oci://ghcr.io/krateo-blueprints/charts/azure-insights-component` at that version.

### Create a Composition

```yaml
apiVersion: composition.krateo.io/vX-Y-Z   # VERSION with dashes, e.g. v0-1-6
kind: AzureInsightsComponent
metadata:
  name: my-component
  namespace: azure-insights-system
spec:
  credentialFrom: ""        # optional: a Secret name; empty inherits from the namespace
  owner:
    name: my-resource-group
  # ... Component spec fields (see values.schema.json)
```

### Check status

```sh
kubectl get azureinsightscomponents.composition.krateo.io -n azure-insights-system
kubectl get components.insights.azure.com -A
```

# Krateo Azure Blueprints

A catalog of [Krateo](https://krateo.io) blueprints that expose **Azure resources** as
self-service Krateo Compositions, backed by
[Azure Service Operator (ASO)](https://azure.github.io/azure-service-operator/).

Each blueprint is a Helm chart whose templates render a **native ASO custom resource** (e.g.
`storage.azure.com/v1api20230101` `StorageAccount`). When you create a Composition, Krateo
renders the chart, the ASO resource lands in the cluster, and ASO reconciles it into the real
Azure resource and reports status back. A sibling `CompositionDefinition` registers each chart
with Krateo.

**289 charts across 46 Azure services.**

## Which API version a blueprint targets

ASO serves several version families per resource — a dated GA version
(`v1api20240101`), a legacy alias (`v20240101`), a preview, and an internal `*storage`
conversion version for each. At ASO v2.21.1, **767 of 1,539 served versions are `*storage`
conversion hubs**, and they are also the ones marked as the storage version.

So the usual "target the storage version" rule is wrong here: it would point every blueprint at
an internal conversion type. Each blueprint targets the **newest GA, non-storage** version,
preferring the `v1api` family.

Four resources are **excluded** because they have no GA version at all — `DiagnosticSetting`
(insights) and all three `databasewatcher` kinds are preview-only. A blueprint is not pinned to
a pre-release.

## Install

1. **Install Azure Service Operator** — see [`docs/installing-controllers.md`](docs/installing-controllers.md).
2. **Configure Azure credentials** — see [`docs/authentication.md`](docs/authentication.md).
3. **Krateo `core-provider`** installed in the cluster.

```
oci://ghcr.io/krateo-blueprints/charts/azure-<service>-<resource>:<version>
```

## Configure

A Composition's `spec` **mirrors the ASO resource `spec`** — including the required `owner`
reference (the parent resource group or resource) and `location`, which are part of the resource
spec rather than Krateo wiring. The one added field is `credentialFrom`, which becomes the
`serviceoperator.azure.com/credential-from` annotation naming a Secret; leave it empty to
inherit the credential from the namespace, then from the operator's global credential.

Krateo's `core-provider` builds the Composition CRD from each chart's `values.schema.json`
**only** — it never reads `values.yaml`.

## Develop

Every blueprint is generated by [`tools/asogen`](tools/asogen) from the upstream ASO CRD and
validated with `helm template`. ASO's CRDs are generated at build time and are not checked into
its repo, so the source is the release bundle:

```sh
gh release download v2.21.1 --repo Azure/azure-service-operator \
  --pattern 'azureserviceoperator_customresourcedefinitions_*.yaml'
go run ./tools/asogen -crd <one-crd.yaml> -out blueprints -lint
```
